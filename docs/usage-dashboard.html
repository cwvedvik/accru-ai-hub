Member firms with licences, active users, adoption, spend and spend limit
Data source and behaviour
Endpoints
/analytics/users carries the group on each user, which is how cost is attributed to a firm. read:spend_limits supplies the limit.
Group mapping
Three firms hold two groups each. Both roll into one firm row. See Data coverage.
Adoption
Renders as a dash when Accru has not supplied a headcount. It is never shown as zero.
Build note
Server-side sort and pagination once the register passes a few hundred rows. At 71 firms client-side is fine.

Spend limits

Firms measured against the limit set on their Claude group, over the last complete calendar month. For a month still in progress this becomes a run-rate projection. This is the page to open before a limit is breached, not after.

Watchlist

Spent in the month Amount over the limit Limit Each bar is scaled to its own limit.
Data source and behaviour
Endpoints
read:spend_limits at group level, /analytics/user_cost_report aggregated per group.
Month shown
The last complete calendar month, because a spend limit is a monthly control and a part-month comparison flatters everyone. For the month in progress, show a straight-line projection instead: month-to-date divided by elapsed days, times days in month. Deliberately simple so a partner can reproduce it by hand.
Caveat
Recent cost sits inside the 30 day revision window, so a figure for the current month can move by a few percent after the fact. Say so next to the number.
Build note
Alerting belongs here, not in a separate tool. Notify the firm owner at 80 percent and the group at 100 percent.

What the numbers on the other pages do not include, and why. The rollout is still in progress, so this page is expected to be busy now and quiet later.

Freshness

Data source and behaviour
Endpoints
read:rbac_groups for the live directory, reconciled against Accru's firm register.
Rule
The live directory is the source of truth for groups. The Accru register is the source of truth for firm names and countries.
Build note
Recompute this reconciliation on every daily run. Groups appear and disappear during rollout, and a stale mapping silently misattributes spend.
